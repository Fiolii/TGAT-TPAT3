# งานประจำวัน: เพิ่มโจทย์และเกร็ดความรู้ใหม่ แล้ว push (ทุกวัน 16:00 · ครบทุกหัวข้อ หัวข้อละ ≥3 ข้อ)

เป้าหมาย: ให้ผู้ใช้เจอโจทย์/เนื้อหา **ใหม่จริง ไม่ซ้ำ** ทุกวัน โดยเพิ่มแพ็กรายวันที่ `data/dq/days/YYYY-MM-DD.json` (และไฟล์ส่วนต่อ `YYYY-MM-DD_2.json`, `_3.json`)
แอปอ่านผ่าน `data/dq/manifest.json` + `data/dq/bundle-YYYY-MM.json` (สร้างโดย `tools/dq_build.mjs`) — **งานนี้แก้ได้เฉพาะ `data/dq/**` เท่านั้น ห้ามแตะโค้ดแอปหรือไฟล์อื่น**

## ขั้นตอน (ทำตามลำดับ ถ้าขั้นไหนล้มเหลวให้หยุดและรายงาน ห้าม push ของที่ยังไม่ผ่านตรวจ)
1. `cd` ไปโฟลเดอร์โปรเจกต์ (ที่มี `tools/DAILY.md`) · `git pull --ff-only origin main` (ถ้า pull ไม่ได้ให้หยุด)
2. ตรวจว่าโค้ดโหลดแพ็กมีอยู่ในรีโมตแล้ว: `git ls-files data/dq_load.js tools/dq_validate.mjs` ต้องมี 2 ไฟล์ ถ้าไม่มี (ยังไม่เคย push ระบบ) ให้หยุดและรายงานว่า "ต้อง push ระบบโหลดแพ็กก่อน"
3. หาวันที่วันนี้ `date +%F` แล้วรัน `node tools/dq_validate.mjs --day <วันนี้>` — มันแสดงว่า**ทุกหัวข้อ**วันนี้มีโจทย์ใหม่กี่ข้อ ขาดอีกกี่ข้อ และไฟล์ถัดไปที่ต้องเขียนชื่ออะไร · ถ้าขึ้น "ครบทุกหัวข้อแล้ว" → จบงาน (ทำครบไปแล้ว)
4. (ไม่บังคับ) `node tools/dq_validate.mjs --coverage` ดูหัวข้อที่โจทย์สะสมน้อยที่สุด เพื่อเติมโจทย์เกินขั้นต่ำให้หัวข้อเหล่านั้นก่อน
5. **เป้าหมายต่อวัน: ทุกหัวข้อ (ทั้ง 24 หัวข้อในตารางด้านล่าง) ได้โจทย์ใหม่อย่างน้อยหัวข้อละ 3 ข้อ รวมราว 72–90 ข้อ** เขียนเป็น 2–3 ไฟล์ "ส่วน" (แต่ละไฟล์ 24–40 ข้อ) ตามที่ `--day` บอก: ส่วนที่ 1 = `data/dq/days/<วันนี้>.json` (มีเกร็ดความรู้ 3–5 รายการ), ส่วนที่ 2 = `<วันนี้>_2.json` (id เริ่ม `dq-YYYYMMDD-41`), ส่วนที่ 3 = `<วันนี้>_3.json` (id เริ่ม `-81`) ไฟล์ส่วนที่ 2 ขึ้นไปไม่ต้องมีเกร็ดความรู้ แต่ละส่วนต้องมีทั้ง 3 กลุ่ม (tpat3/tgat/alevel) กลุ่มละ ≥3 ข้อ แบ่งหัวข้อให้สมดุลทั้งส่วน
6. ทุกครั้งที่เขียนเสร็จหนึ่งส่วน ให้รัน `node tools/dq_validate.mjs data/dq/days/<ไฟล์ส่วนนั้น>.json` ต้อง "ผ่านการตรวจ ✓" (exit 0) ก่อนเขียนส่วนต่อไป — ถ้าไม่ผ่านให้แก้แล้วตรวจใหม่ไม่เกิน 3 รอบ ถ้ายังไม่ผ่านให้ลบไฟล์ส่วนนั้นทิ้ง แล้วไปขั้น 7 ด้วยส่วนที่ผ่านแล้ว และรายงานหัวข้อที่ยังขาด · เขียนครบทุกส่วนแล้วรัน `--day <วันนี้>` อีกรอบเพื่อยืนยัน
7. `node tools/dq_build.mjs` (สร้าง bundle + manifest) · ถ้าขนาดไฟล์ `data/dq/bundle-*.json` รวมเกิน 6 MB ให้หยุดและรายงานผู้ใช้ (ต้องออกแบบการแบ่งโหลดใหม่ — ที่ ~80 ข้อ/วัน โจทย์ราว 150 KB/วัน เดือนหนึ่งจะใกล้ 4.5 MB)
8. `git add data/dq` เท่านั้น (ห้าม `git add -A` / `git add .`) → `git status --short` ต้องเห็นเฉพาะไฟล์ใน `data/dq/`
9. `git commit -m "Daily content YYYY-MM-DD: N questions, M notes"` ปิดท้ายข้อความด้วยบรรทัด `Co-Authored-By: Claude <noreply@anthropic.com>`
10. `git push origin main` · รายงานสั้น ๆ: วันที่ จำนวนข้อต่อกลุ่ม หัวข้อที่เขียน และผลการตรวจ

## ข้อกำหนดของแพ็ก
ไฟล์: `{ "date": "YYYY-MM-DD", "questions": [...], "notes": [...] }`
- **โจทย์ราว 72–90 ข้อ/วัน (แบ่งเป็น 2–3 ไฟล์ส่วน ไฟล์ละ 24–40 ข้อ)** ครบทุกหัวข้อหัวข้อละ ≥3 ข้อ: TPAT3 5 หัวข้อ, TGAT1 4, TGAT2 4, TGAT3 4, A-Level คณิต 3 + ฟิสิกส์ + เคมี + ชีววิทยา (A-Level ใส่แบบตอบเป็นตัวเลขรวมวันละ ≥6 ข้อ) · ระดับ ง่าย 20% / กลาง 45% / ยาก 35% (`diff` 1/2/3) · **ห้ามลดคุณภาพเพื่อให้ได้จำนวน** — ถ้าข้อไหนไม่แน่ใจเฉลย ให้ตัดทิ้งแล้วเขียนข้อใหม่ทดแทน
- **เกร็ดความรู้ 3–5 รายการ/วัน** (`notes` ในไฟล์ส่วนที่ 1 เท่านั้น): วิธีคิดลัด กับดักที่พบบ่อย หรือแนวคิดที่ต่อยอดจากโจทย์วันนี้ ยาว 120–900 ตัวอักษร
- **เขียนเอง ห้ามคัดลอกข้อสอบจริง/หนังสือเรียน/เว็บใด** (ลิขสิทธิ์) — ค้นเว็บเพื่อศึกษาขอบเขตเนื้อหา สไตล์ข้อสอบ และแนวคิดได้ แล้วเขียนโจทย์ใหม่ด้วยตัวเลข/บริบท/ตัวเลือกของตัวเอง
- **ทุกข้อต้องมีเฉลยที่ถูกต้องข้อเดียวชัดเจน** ข้อที่ต้องคำนวณให้ **รันโค้ด (node) ตรวจคำตอบจริงก่อนเขียนลงไฟล์** ห้ามเดา · ตัวเลือกผิดมาจากข้อผิดพลาดยอดฮิตที่ฟังดูสมเหตุสมผล ไม่ใช่ตัวเลือกที่ผิดแบบเห็นชัด
- **ห้ามให้ข้อถูกเดาได้จากความยาว**: ตัวเลือกทุกข้อต้องยาว/ละเอียดใกล้เคียงกัน (ข้อผิดต้องฟังดูสมเหตุสมผลและมีรายละเอียดพอ ๆ กับข้อถูก ไม่ใช่ประโยคสั้นหรือสุดโต่งที่ผิดทันที) ข้อถูกควรเป็นข้อที่ยาวที่สุดไม่เกิน ~25% ของโจทย์ และยาวไม่เกิน 1.2 เท่าของค่าเฉลี่ยข้อผิด — ตัวตรวจจะไม่ผ่านถ้าเกิน (`node tools/dq_validate.mjs --lengths` ตรวจทั้งคลัง)
- โจทย์ควรยากพอและหลากหลาย: หลายขั้นตอน ข้อมูลเกินจำเป็น หน่วยปนกัน ตาราง/ข้อมูลเป็นข้อความ "ข้อใดถูก/ไม่ถูกต้อง" ชุดข้อความ ก ข ค ง ฯลฯ · TGAT1 ใช้ภาษาอังกฤษ (ใช้ `passage` สำหรับบทอ่าน) · ไม่ทำโจทย์ที่ต้องมีรูปภาพ (ห้ามมี `fig`)
- ตัวอักษรพิเศษ: ตัวห้อย/ตัวยกใช้ได้ เช่น `H₂O`, `x²`, `E_k`, `x^2` (แอปแปลงให้) · ข้อความล้วน ห้ามมี HTML

### รูปแบบโจทย์ปรนัย (ตัวเลือก 5 ข้อ)
```json
{ "id": "dq-20261116-01", "group": "tpat3", "subject": "TPAT3", "topic": "เชิงตัวเลข", "diff": 3,
  "q": "โจทย์...", "c": ["ก", "ข", "ค", "ง", "จ"], "a": 2,
  "exp": "วิธีทำ/เหตุผลของข้อที่ถูก (หลายบรรทัดได้ ใช้ \n)",
  "why": ["ข้อ ก ผิดเพราะ...", "ข้อ ข ผิดเพราะ...", "", "ข้อ ง ผิดเพราะ...", "ข้อ จ ผิดเพราะ..."],
  "tip": "เคล็ดลับสั้น ๆ (ไม่บังคับ)", "passage": "บทอ่าน (ไม่บังคับ)" }
```
- `id` = `dq-YYYYMMDD-NN` (ส่วนที่ 1 เริ่ม 01 · ส่วนที่ 2 เริ่ม 41 · ส่วนที่ 3 เริ่ม 81 ต่อเนื่องกัน ห้ามซ้ำข้ามไฟล์) · ฟิลด์ `date` ในทุกไฟล์ส่วนใช้วันที่เดียวกัน (ไม่ใส่ `_2`) · `why` ต้องมี 5 ช่อง ช่องของข้อที่ถูกเป็น `""` · `a` = ตำแหน่งข้อที่ถูก 0–4 (แอปสลับตำแหน่งให้สมดุลเอง) · ตัวเลือกที่เป็นตัวเลขล้วนให้เรียงน้อย→มาก
### รูปแบบโจทย์ตอบเป็นตัวเลข (ใช้กับ A-Level)
```json
{ "id": "dq-20261116-09", "group": "alevel", "subject": "ฟิสิกส์", "topic": "ฟิสิกส์", "diff": 2, "type": "num",
  "q": "โจทย์...", "ans": 4, "tol": 0.01, "unit": "s", "exp": "วิธีทำ...", "wrong": [[8, "คำตอบผิดที่พบบ่อย ได้มาเพราะ..."], [16, "..."]] }
```


## ความปลอดภัยของงาน
- แก้/commit/push เฉพาะ `data/dq/**` · ไม่ใช้ `--force` · ไม่แก้ประวัติ git · ไม่ push ถ้า validator ไม่ผ่าน
- ถ้า `git status` มีไฟล์อื่นที่ผู้ใช้แก้ค้างอยู่ ให้ปล่อยไว้ ห้าม stage/commit/ลบ
- ถ้าเกิดข้อสงสัยว่าเนื้อหาผิดวิชาการ ให้ตัดข้อนั้นออก (ดีกว่าใส่ข้อที่เฉลยผิด)
